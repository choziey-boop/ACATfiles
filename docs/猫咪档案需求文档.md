# 校园猫咪相册小程序 - 项目需求文档 (PRD) v2.0

> 文档版本：v2.0
> 更新日期：2026-09-07
> 项目性质：个人非盈利校园公益项目
> 说明：本版本融合了需求评估中的优化建议，补充了后台管理、状态流转、防刷机制及合规隐私要求，具备直接进入开发的条件。

## 1. 项目概述

### 1.1 项目背景
本项目旨在开发一款校园猫咪相册小程序。通过展示校园流浪猫的档案、动态和领养信息，方便校友及社会爱心人士了解校园猫咪现状，并为有领养意向的用户提供官方申请渠道。

### 1.2 项目目标
- 建立校园猫咪的电子档案库，记录每只猫咪的生活轨迹。
- 提供安全、合规的领养申请通道，帮助流浪猫找到永久家庭。
- 营造文明、友善的校园宠物文化氛围。

### 1.3 技术架构
- **前端**：微信小程序原生框架（WXML + WXSS + JS/TS）。
- **后端**：建议使用微信云开发（数据库 + 云存储 + 云函数）或自建 Serverless 服务。
- **合规要求**：严格遵守《微信小程序运营规范》及《个人信息保护法》。

## 3. 核心页面功能需求

### 3.1 首页 (Home)

#### 3.1.1 公告板块
- **位置**：顶部置顶区域。
- **内容**：展示置顶的校园通知、猫咪救助公告或紧急寻猫启事。
- **交互**：支持滚动或多条列表展示，点击公告卡片可跳转至详情页查看完整内容（图文混排）。

#### 3.1.2 动态板块（合规调整：仅限管理员发布，无 UGC）
- **内容**：展示校园猫咪的日常动态（图文形式，如“大橘今天又在图书馆晒太阳”）。
- **排序**：按照发布时间倒序排列。
- **互动限制**：不提供评论功能，规避社交类目审核要求。
- **互动功能**：每条动态右下角支持 **“点赞”**（仅累加数字，不展示用户头像列表，简化隐私风险）。
- **引流交互**：动态卡片底部或右上角增加 **“去看看”** 轻触按钮，点击直接跳转至该动态关联的猫咪详情页。

### 3.2 猫咪档案页 (Cat Archives)

#### 3.2.1 搜索与筛选
- **搜索栏**：支持输入猫咪昵称、毛色（基于标签）等关键词进行模糊搜索。
- **筛选器**：支持按性别（公/母）、绝育状态（已绝育/未绝育）、校区/区域等多条件组合筛选。

#### 3.2.2 猫咪列表
- **布局**：采用瀑布流或网格卡片形式展示。
- **卡片内容**：猫咪封面图、名字、性别图标、绝育状态角标。
- **加载优化**：列表需接入 **骨架屏（Skeleton Screen）**，提升图片加载过程中的用户体验。
- **状态过滤**：默认列表中**隐藏**“已领养”状态的猫咪，仅展示“待领养”、“校园常驻”或“毕业回喵星”等状态（“已领养”猫咪仅可通过详情页直链访问）。

#### 3.2.3 猫咪详情页
点击列表卡片进入，页面结构如下：

- **视觉元素**：
  - 顶部置顶高清头图（支持左右滑动查看多张主图）。
  - 下方展示该猫咪的 **“相册图片集”**。
  - *增强体验*：点击相册图片进入全屏沉浸式预览（支持双指缩放）。
- **基础档案**：性别、预估年龄、是否绝育、绝育时间。
- **故事介绍**：一段关于该猫咪性格、常出没地点、外号等简单介绍。
- **虚拟云吸猫互动（合规调整：无真实资金往来）**：
  - 提供 **“给TA塞小鱼干”** 按钮。
  - **防刷机制**：同一用户（基于 `openid`）对同一猫咪 **24 小时内仅能投喂 1 次**。
  - 交互反馈：点击后，该猫咪的“今日收获小鱼干数 / 人气值”+1，并伴随简易的喂食动效。
- **状态提示（重要补充）**：
  - 若该猫咪状态为“已领养”，页面顶部显示醒目横幅：`🎉 此猫已被领养，祝它幸福！`，并隐藏所有领养相关入口。

### 3.3 领养中心页 (Adoption)

#### 3.3.1 待领养列表
- **数据范围**：仅展示状态为“待领养”的猫咪。
- **排序**：默认按照最后更新时间倒序排列（新发布/新更新的在最前）。
- **视觉权重**：支持后台为特定猫咪（如怀孕母猫、紧急离校猫咪）配置 **“急寻领养”** 红色角标。

#### 3.3.2 领养申请流程
- **入口**：进入待领养猫咪详情页，页面底部常驻 **“我想领养”** 按钮（Fixed 定位）。
- **领养申请表单（合规提示：需配置隐私保护指引）**：
  - 字段包括：
    1. 联系方式（手机号 / 微信 ID）- **必填**。
    2. 领养原因 - 文本输入框。
    3. 居住情况简介（如：自有住房/合租、是否有防盗网、是否允许养宠等）- 文本输入框。
  - **合规提示**：页面显著位置标注 *“本程序为非盈利校园公益，收集信息仅用于领养资格审核，不涉及任何费用”*。
- **提交反馈（闭环优化）**：
  - 提交后跳转至 **“申请成功页”**，提示：“您的申请已提交，管理员将在 **3 个工作日内** 通过预留方式联系您。”
  - **防重复机制**：同一用户针对同一只猫咪，若已有“待审核”状态的申请单，再次点击“我想领养”时，提示“您已提交过申请，请勿重复提交”。

### 3.4 关于我们页 (About Us)
- **内容区域**：预留富文本展示区域，用于介绍小程序发起背景、校园猫咪协会/团队简介、领养须知等。
- **现状**：具体内容暂时留空，待运营方后续通过后台录入。

## 4. 后台管理系统（CMS）需求（补充重点）

**> 若无后台管理，小程序无法持续运营。因此必须包含以下最简功能模块：**

### 4.1 猫咪信息管理
- 列表展示所有猫咪，支持增删改查。
- 核心字段编辑：名字、编号、性别、年龄、状态（待领养/已领养/毕业等）、绝育状态、绝育时间、简介描述。
- **图片管理**：支持上传头图、上传相册多图、拖拽排序。

### 4.2 动态与公告发布
- 富文本编辑器（或简化的 Markdown 编辑器）。
- 支持上传封面图/配图。
- 动态支持关联指定猫咪（便于首页点击跳转）。

### 4.3 领养审核管理
- 列表展示所有领养申请单。
- 审核操作：点击“通过”或“拒绝”。
- **拒绝操作**：强制要求填写拒绝原因（如“居住条件不满足”），该原因将以消息/站内信形式反馈给用户（开发需预留此接口）。

## 6. 非功能性与合规需求

### 6.1 合规与隐私（审核必过项）
- **用户隐私弹窗**：小程序启动时必须通过 `wx.getPrivacySetting` 检测，并弹出《用户隐私保护指引》，用户明确点击 **“同意”** 后，方可收集表单信息（手机号、微信号等）。
- **`app.json` 配置**：必须开启 `"__usePrivacyCheck__": true`。
- **数据加密**：用户填写的联系方式在数据库中进行加密存储，管理员后台脱敏显示。

### 6.2 性能要求
- **图片加载**：必须使用 CDN 加速，列表图片启用懒加载（`lazy-load`）。
- **缓存策略**：首页公告和动态可本地缓存 5 分钟，减少数据库读取压力。
